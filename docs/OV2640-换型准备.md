# OV2640 换型准备（从 OV7670 迁过去）

> 起因：`m00219`「我感觉效果太差了，我之后准备换成 ov2640 的，你先去找找资料，等我新的到了就换」。
> 这份文档就是"新的到了以后照着做"的那张纸。固件已经写好了：`firmware/e4-ov2640`。

## 0. 一句话结论

值得换，而且换过去正好绕开 OV7670 死磕了两小时的那几个坑：

| | OV7670（现在） | OV2640（要换的） |
|---|---|---|
| 出图方式 | 裸 RGB565，一帧 614400 字节 | **传感器硬件 JPEG**，VGA 一帧约 20~40 KB |
| UART 传一帧 | 6.7 秒 @921600 | 0.3~0.6 秒 |
| PCLK | 必须手动压到 XCLK/3 才不花 | JPEG 模式驱动自己 `pclk_div=8`，天然慢、对烂线友好 |
| 分辨率 | 640×480 | 最高 1600×1200 |
| QVGA | **坏的**（DCW 降采样，整行一个颜色） | 正常 |

一句人话：**OV7670 之所以难搞，是因为它把"压缩/降采样"的活全丢给 ESP32，而面包板上的线撑不住那个速率；OV2640 自己会压，速率问题就没了。**

## 1. 接线（模块丝印 → ESP32-S3 引脚）

模块丝印的写法各家不一样（`SCL/SIOC`、`SDA/SIOD`、`D0..D7` 或 `D2..D9`），**按信号名对，不要按位置对**。

| 信号 | 模块上常见丝印 | 我们的 GPIO | 备注 |
|---|---|---|---|
| 电源 | 3.3V / VCC / DVDD | 3V3 | **先量**：少数模块只吃 2.8V，5V 会烧 |
| 地 | GND | GND | 多并一根到模块，不要和舵机共地噪声 |
| SCCB 时钟 | SCL / SIOC / SCLK | **40** | 上拉通常在模块上 |
| SCCB 数据 | SDA / SIOD / SDATA | **1** | |
| 主时钟 | XCLK / MCLK / MCK / CLK | **18** | 由 ESP32 的 LEDC 产生 20MHz；**模块自带晶振时这根不接**，见 §1.1 |
| 像素时钟 | PCLK / PIXCLK / **DCLK** | **21** | 有的模块丝印写 `DCLK`（data clock），就是 PCLK，不是另一个脚 |
| 场同步 | VSYNC | **38** | |
| 行同步 | HREF / HSYNC | **39** | |
| 数据位 0 | D0 / Y2 | **8** | |
| 数据位 1 | D1 / Y3 | **9** | |
| 数据位 2 | D2 / Y4 | **10** | |
| 数据位 3 | D3 / Y5 | **11** | |
| 数据位 4 | D4 / Y6 | **12** | |
| 数据位 5 | D5 / Y7 | **13** | |
| 数据位 6 | D6 / Y8 | **14** | |
| 数据位 7 | D7 / Y9 | **17** | |
| 复位 | RESET / RST | **48** | ⚠️ 必须接，见 §5.1 |
| 掉电 | PWDN / PDN | GND | 低电平 = 正常工作；模块内部无上拉时必须接死 |
| 闪光 | STROBE / FLASH / LED | 悬空 | 不用 |

> 和 e3 完全同一套线 —— 换模块时把 18 根线从旧模块挪到新模块就行，不用改代码、不用改接线图。

### 1.1 模块上没有 XCLK / MCLK 怎么办

先看清楚是哪种情况：

1. **板上自带晶振**（模块背面有个小金属壳或小黑方块，上面印 `12.000` / `24.000` / `20.000`）⇒
   传感器自己有时钟，ESP32 **不要**再接 XCLK。接线表里 XCLK 那行空着，固件里把
   `firmware/e4-ov2640/main/main.c` 的 `#define E4_MODULE_HAS_OWN_OSC 0` 改成 `1`
   （驱动里 `pin_xclk = -1` 会整段跳过 XCLK 输出，`driver/esp_camera.c:186`）。
2. **丝印叫别的名字**（`MCLK` / `MCK` / `CLK` / `XCL` / `XCLK0`）⇒ 还是 XCLK，照接 GPIO18。
3. **一个脚都没有**、板子也看不出晶振 ⇒ 大概率是带 FIFO（AL422B）的模块，那套接线逻辑完全不同
   （读的是 FIFO，不是传感器直出），先拍照确认型号再说，别硬接。

`NC` 就是 "no connection"，不接。

### 1.2 这块实物（1688 红色 OV2640 模块）的确定信息

供应商后来给了原理图 + 引脚表，**不用再猜了**：

- **`Y1 = 12.000MHz 有源晶振`**（接 VCC3.3，输出 `OV_XCLK`）⇒ 板上自带时钟，`E4_MODULE_HAS_OWN_OSC = 1`，GPIO18 空着。
- 电源：`U1 XC6219B132MR` 5V→3.3V（`VCC3.3`）；`U2 RT9193-2.8` →`VCC2.8` 供 `OV_AVDD`/`OV_DVDD`/`OV_DOVDD`。
  ⇒ **排针上的 3.3V 是芯片输入侧，不要接 5V。**
- 排针是 **9×2 双排（P1）**，脚号顺序（供应商《引脚说明》）：

| 脚号 | 名称 | 方向 | 接到 |
|---|---|---|---|
| 1 | GND | — | GND |
| 2 | VCC3.3 | 电源输入 | 3V3 |
| 3 | OV_SCL | IN | GPIO40 |
| 4 | OV_VSYNC | OUT | GPIO38 |
| 5 | OV_SDA | INOUT | GPIO1 |
| 6 | OV_HREF | OUT | GPIO39 |
| 7 | OV_D0 | OUT | GPIO8 |
| **8** | **OV_RESET** | IN（低有效） | **GPIO48** |
| 9 | OV_D1 | OUT | GPIO9 |
| 10 | OV_D2 | OUT | GPIO10 |
| 11 | OV_D3 | OUT | GPIO11 |
| 12 | OV_D4 | OUT | GPIO12 |
| 13 | OV_D5 | OUT | GPIO13 |
| 14 | OV_D6 | OUT | GPIO14 |
| 15 | OV_PCLK（丝印可能写 DCLK） | OUT | GPIO21 |
| 16 | OV_D7 | OUT | GPIO17 |
| **17** | **OV_PWDN** | IN（**高电平掉电**） | **GND** |
| 18 | NC | — | 空着 |

  ⚠️ 两个最容易接错的地方：**RESET 在第 8 脚**（夹在 D0 和 D1 中间），**PWDN 在第 17 脚**（夹在 D7 和 NC 中间），
  不是收在排针末尾。PWDN 是高有效，接 3.3V 或者悬空到高电平 = 传感器一直睡，SCCB 读回全 0。
  ⚠️ 脚号来自供应商表，**实物接线以板子丝印文字为准**：一根一根念着丝印接，接完再数一遍 18 根有没有错位。

## 2. 固件：`firmware/e4-ov2640`（已写好、已编译通过）

从 `e3-ref` 复制出来，只改了这些（其余包括引脚、UART 外壳都保持原样）：

```c
.pin_reset      = 48,                  // 不再填 -1
.xclk_freq_hz   = 20000000,            // OV2640 标准时钟
.pixel_format   = PIXFORMAT_JPEG,      // 关键：硬件 JPEG
.frame_size     = FRAMESIZE_VGA,       // 640x480；想更大改 FRAMESIZE_UXGA
.jpeg_quality   = 12,                  // 0~63，越小越清晰
.fb_count       = 2,                   // JPEG 才允许多缓冲
.grab_mode      = CAMERA_GRAB_LATEST,  // 总是拿最新一帧
```

去掉了：OV7670 专属的 `COM10`、`CLKRC` 两个自定义寄存器、寄存器 DUMP 表、Wi-Fi。
保留了：串口命令通道（只是命令换成 OV2640 能用的那几个）。

**帧格式**（和 e3 同一个外壳，数据换成 JPEG）：

```
META,JPEG,<字节数>\n
<JPEG 原始字节，以 FF D8 开头、FF D9 结尾>
\nEND\n
```

**串口命令**（921600，`\n` 结尾）：

| 命令 | 作用 |
|---|---|
| `PUSH 1` / `PUSH 0` | 开/关推帧（默认关，先看日志） |
| `RATE 500` | 推帧间隔毫秒，默认 200 |
| `REG 12` | 读 bank0 寄存器 0x12 |
| `REG 12 04` | 写 bank0 寄存器（写完回读确认） |
| `BANK 01` | 切 OV2640 的寄存器 bank（写 0xFF） |
| `HELP` | 命令表 |

> 为什么默认不推帧：插上线先让启动日志（PID、预热帧字节数）打出来；日志和图像共用 UART0，同时开就会互相插字节。

## 4. 排障表（先按这张表查，别瞎改代码）

| 现象 | 先查什么 |
|---|---|
| `0x105`（`ESP_ERR_NOT_FOUND`） | SCCB 没通：SCL/SDA 接反、没上拉、模块没供电、**RESET 没接/接反** |
| `0x106`（`ESP_ERR_NOT_SUPPORTED`） | SCCB 通了但 PID 不认识：买错模块 / 模块是并口但没供电 / 读到 0xFF |
| PID 读出来是 0x00 或 0xFF | 这个就是"寄存器读不到"：先量 VCC，再查 SDA/SCL，最后查 RESET 是否被拉低 |
| 能枚举、能出帧，但全黑 | 镜头盖 / 排线没插到底 / 曝光没收敛（多等 1 秒）/ 闪光灯挡住 |
| 花屏、彩条乱跳 | **先把 XCLK 从 20MHz 降到 10MHz**（`.xclk_freq_hz = 10000000`），再查杜邦线长度 |
| 只有第一帧正常，后面全烂 | 杜邦线太长/接触不良导致 PCLK 采样边缘；降 XCLK、缩短线、加 GND |
| 帧率低得离谱 | `RATE` 调小没用 —— UART 就是这个速度；要快就上 Wi-Fi/HTTP |
| 图像发绿/发紫 | OV2640 的 AWB 没收敛：多抓几帧再看；或 `REG` 调 bank0 的 0x41/0x42（自动白平衡） |

## 5. 两个必须记住的坑

### 5.1 RESET 不能悬空（OV7670 用两小时换来的）

OV7670 那次：RESET 拔了（`CAM_PIN_RESET = -1`），现象是——

* 电气测量全正常（3.3V、SCCB 有波形）；
* 但读出来 `COM7=0x00`（YUV 模式）、HSTART/HSTOP 全是上电默认值，**和驱动写的完全不一样**；
* 图像是彩条/品红横纹垃圾，串口刷 `cam_hal: FB-OVF`；
* 偶尔又能正常枚举，像"时好时坏"。

真因：模块上没有上拉，悬空的 RESET 让芯片随机复位 —— 每次驱动写完寄存器，芯片又复位回默认值。
把 RESET 接回 GPIO48（`CAM_PIN_RESET = 48`）后，**所有寄存器立刻留住了**（`COM7=0x04` RGB565、`COM15=0xD0`）。

⇒ OV2640 同样处理：**RESET 接 GPIO48，代码里填 48**；PWDN 接 GND，代码里填 -1。

### 5.2 面包板 + 杜邦线的上限比想象的低

OV7670 在 VGA 下满屏彩色雪花，逐项排查后确认：**不是曝光、不是镜头，是 PCLK 12MHz 下 ESP32 采到的是"还没稳定的数据"**。

判据（相邻像素平均绝对差，越小越干净）：

| CLKRC | PCLK | 平均绝对差 |
|---|---|---|
| 0x00 | XCLK | 1684 |
| 0x01 | XCLK/2 | 1346 |
| **0x02** | **XCLK/3** | **535** |
| 0x03 | XCLK/4 | 705 |

压到 XCLK/3 后 3 帧互相关 0.93~0.97（之前 0.43~0.5）。**结论：这条线只稳到 4MHz 量级的 PCLK。**

OV2640 的 JPEG 模式驱动默认 `pclk_div=8`（UXGA 是 12），PCLK 本来就很慢 —— 这是它在这块面包板上最大的优势。
真要是还花，按 §4 把 XCLK 降到 10MHz，`pclk_div` 不变，PCLK 就只剩 1.25MHz。

## 6. OV7670 复盘（为什么不再抢救）

| 结论 | 证据 |
|---|---|
| QVGA 不能用 | 320×240 抓出来 240 行全一样、每行只有一个颜色；彩条测试却 8 条全对 ⇒ 数字通路没问题，坏在 DCW 降采样 |
| VGA 可以出图 | 关掉 DCW（`0C/3E/72/73/A2`）、改 `FRAMESIZE_VGA` 后 480/480 行都不同，能看到亮块/暗区 |
| 雪花是采样时序 | `CLKRC` 扫描（见 §5.2），压到 XCLK/3 后平均绝对差从 1684 降到 535 |
| 还有一道横断口 | 每帧行间差最大固定在 row 357–358；按 960 字节重排是斜向撕裂 ⇒ 1280 字节/行是对的，断口是"传感器这一帧只给了约 460800 字节" |
| 画面本身 | 大幅离焦/近距离色块（红/紫/白），颜色脏、噪点重 —— 不是代码能救的 |

保留 `firmware/e3-ref` 不动，当"OV7670 能出图的最小参考"。

## 7. 换型之后的下一步（不是现在做）

* **要照片**：`PUSH 1` + `RATE 2000` 当"每 2 秒一张"，或写个 HTTP 服务（OV2640 的 JPEG 直接 `httpd_resp_send` 就是 MJPEG 流）。
* **要进身体**：等 e4 出图稳定后，把"拍照"接进 `body_say` 那条 MQTT 通道（`mcp-body` 那边加一个 `camera` 工具）。
* **要更清晰**：先 `jpeg_quality` 调到 8~10，再考虑 `FRAMESIZE_SVGA/UXGA`（UART 会变慢，最好换 Wi-Fi）。
* **OV2640 调色**：`sensors/ov2640.c` 里有完整 settings 表和 bank 结构，改之前先在 `REG`/`BANK` 上试，别直接改驱动。

## 8. 跨网推流实测（2026-10-31 傍晚，三条路都跑过）

目标：PC 和板子**不在一个网段**时也能看图。PC 只有以太网 `192.168.77.5/24`，
板子 Wi-Fi 拿的是 `192.168.1.105/24`，直连 HTTP（`http://192.168.1.105/stream`）永远不通。

| 路径 | 实现 | 实测帧率 | 适用 |
|---|---|---|---|
| 串口 | `tools/cam_stream.py`（COM4 @1.5Mbps） | **9.9~10.2 fps** 稳 | 板子插在这台机器上 |
| 反向 TCP | 固件 `main/net_push.c` → PC `tools/cam_wifi.py --port 8767` | 板侧 4.8~6.7 fps，PC 只收到 **0.3~2.1 fps**（跨 NAT 抖动 1~3s） | 不推荐 |
| MQTT | 固件 `main/mqtt_cam.c` → PC `tools/cam_mqtt.py` | **2.4~5.1 fps**（有抖动） | 跨网唯一可用 |

### 8.1 broker 就是 e1 那个

```python
# tools/body_config.py:37
"broker": "i1e78188.ala.cn-hangzhou.emqxsl.cn", "brokerPort": 8883, "brokerTls": True,
```
摄像头固件 `CAM_TOPIC_BASE "whale-8f2a5c31"` 就是 e1 的主题前缀，账号密码也取自 `secrets.h` 的
`MQTT_USER/MQTT_PASS`。**不需要再配第二套 EMQX。**

### 8.2 但它卡在“每秒消息条数”，不是带宽

| 分辨率 | 帧大小 | 实测 |
|---|---|---|
| VGA 640x480 | 10.1 KB | 4.6 fps（45 KB/s） |
| QVGA 320x240 | 3.9 KB | 5.1 fps（19 KB/s） |

帧小 2.6 倍，帧率只涨 11% ⇒ **不是带宽，是每帧那一次“发出去到落地”的往返**。
`tools/body_mqtt.py:40-49` 早记过同一件事：EMQX Serverless 上限约 **11 包/秒**。
所以跨云想更快，只能减少“帧”这个单位（`RATE`/降帧率），不能指望放大帧。

### 8.3 固件命令（主题 `<base>/cam/cmd`）

```
STREAM 1|0        开/关推流
RATE <ms>         帧间隔，0 = 尽快（实际受上面的上限约束）
SNAP              单发一张
SIZE VGA|QVGA|SVGA|UXGA   运行时改分辨率（JPEG 下切换后最好关再开推流）
BAR 1|0           内置彩条
HELP
```
上行：`<base>/cam/jpeg`，就是裸 JPEG 字节（没有 META 头，SOI/EOI 自带）。

### 8.4 PC 侧

```bash
python -u tools/cam_mqtt.py --stream 1 --rate 0     # 起在 http://127.0.0.1:8765/
python -u tools/cam_mqtt.py --snap --save a.jpg     # 单张
```
它复用 `cam_wifi.py` 的 `LATEST/STATS/Handler`，所以 `/stats`、`/snap.jpg`、`/stream` 都在，
`seq/fps/age` 用来判断“板子没发”还是“云到 PC 丢了”。

### 8.5 还差一步

* ✅ 反向 TCP 已**默认关掉**：`firmware/e4-ov2640/main/main.c` 的 `#define NET_PUSH_ENABLE 0`
  （`net_push.c` 源码保留，改回 1 就能再试）。关掉后日志里不再每 8 秒刷一行 `push: 连不上`。
* 板侧 5 秒一次 `板侧推流：x.x fps`，和 PC 的 `seq` 对照就能定位丢在哪一段。

## 9. 并进身体：`firmware/e5-body-cam`（2026-10-31 晚，已实物跑通）

e4 是"单独测摄像头"的工程。**真身体用 e5**：它是 `e1-breadboard` 复制来的，
耳朵（INMP441）+ 嘴（MAX98357）+ 屏幕（SSD1306）+ 眼睛（OV2640）在**同一个固件、同一条 MQTT 连接**里。

**接线一根没改**（这就是当初敢直接抄 e1 的原因）：

| 子系统 | GPIO |
|---|---|
| 麦克风 | BCLK 5 / WS 4 / DIN 6 |
| 功放 | BCLK 15 / LRC 16 / DIN 7 |
| 屏幕 | SDA 41 / SCL 42 |
| 按键 | BOOT 0 |
| **摄像头** | D0..D7 = 8,9,10,11,12,13,14,17 / PCLK(DCLK) 21 / VSYNC 38 / HREF 39 / SCCB 40(SCL)/1(SDA) / RESET 48 / PWDN→GND / XCLK 空（模块自带晶振） |

主题与命令（前缀 `whale-8f2a5c31`，跟 e1 完全一样，不用另配 broker）：

```
<base>/cam/jpeg   板→PC   JPEG 原始字节（VGA 640x480，一帧 10~14KB）
<base>/cmd        PC→板   CAM SNAP | CAM STREAM 0|1 | CAM RATE ms |
                          CAM SIZE VGA|QVGA|SVGA|UXGA | CAM QUAL 0-63 | CAM INFO
```

PC 侧一条命令拿照片（返回 JSON + 文件路径）：

```bash
python -u tools/body_camera.py --base whale-8f2a5c31 --json
```

它同时往 `<base>/cam/cmd` 发 `SNAP`（e4 听）和 `<base>/cmd` 发 `CAM SNAP`（e5 听）——
所以 e4/e5 两块固件它都能用。**默认 base 是 d8 的 `whale-1bb62897`，必须带 `--base`。**

### 9.1 合并时踩的三个坑（e5 里的处理，别改回去）

1. **开机 995ms panic**：`E i2c: CONFLICT! driver_ng is not allowed to be used with this old driver`。
   OLED 走 esp_lcd（driver_ng），esp32-camera 2.1.8 仍走老 `driver/i2c`，
   老驱动的 constructor 一看见 driver_ng 就 `abort()`。解法：`sdkconfig` +
   `sdkconfig.defaults` 都设 `CONFIG_I2C_SKIP_LEGACY_CONFLICT_CHECK=y`（屏幕 I2C0、SCCB I2C1，互不相干）。
   ⚠️ 不要改成用 esp32-camera 的 `sccb-ng.c`——那条路要求 IDF ≥5.4，5.3 编不过。
2. **`cam_init` 重名**：esp32-camera 内部已有 `cam_init()`，我们的同名会
   `multiple definition`（链接期才炸）。e5 里统一 `eye_*`。
3. **JPEG 下运行期改分辨率 = 死**：`set_framesize()` 返回 0，之后一直
   `cam_hal: Failed to get frame: timeout`。e5 的 `eye_set_size()` 改完会
   `esp_camera_deinit()` + 重新 `eye_init()`。

### 9.2 实测帧率（e5，VGA q12）

| 场景 | 结果 |
|---|---|
| `CAM SNAP` 单张 | 11KB，1 秒内落地 |
| 连续推流 VGA | 1.3~2.7 fps |
| 连续推流 QVGA | 2.3 fps |
| 板侧自报 | 取帧 180~880ms / 发布 240~900ms |

吞吐约 **14 KB/s ≈ 一个 MSS 往返**，跟帧大小几乎无关（QVGA 帧小 2.6 倍只快 10%）
⇒ 卡在"每次 publish 等 ACK"，不是带宽。e4 单摄像头固件同一天能到 8.8fps，
所以**多出来的那部分开销值得再查一次**（先单独跑 cam_task、再关屏幕 UI 对比）。

### 9.3 带出门：板子自己上网就行

不需要插电脑、不需要和 PC 同一个网段——消息都走云端 EMQX。
只要有 Wi-Fi（家里路由器 / 手机热点），板子就能连上，她的脑子在家里 PC 上照常收发。

`firmware/e5-body-cam/main/secrets.h`：

```c
#define WIFI_AP_LIST     { WIFI_SSID, WIFI_PASS },      /* 家里 */     { "xwb", "xwb123456" },        /* 手机热点（2.4GHz） */
```

* 按顺序试，每个名字试 6 次换下一个；连上会打 `（网络："xxx"）`。
* 30 秒全连不上：自动 `esp_wifi_scan_start` 扫一遍，把附近 Wi-Fi 的名字/rssi/信道打出来。
* ⚠️ 板子只认 2.4GHz；iPhone 要开"最大兼容性"。
* ⚠️ 串口日志波特率：**e5 = 115200**，e4 = 1500000，别拿错。
